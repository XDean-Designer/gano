# 开发提示词 · 工作人员禁止领取联盟券（29S）

可直接整段复制给开发人员的 AI 工具。产品口径已写入 PRD v1.25（决策 **29S**）。

---

你是「剑琅美遇」微信小程序后端/全栈开发助手。请修复联盟活动领券漏洞，并给出可落地改动。

## 背景

联盟核销活动进行中。已发现顾问或店员用本人微信走顾客领券流程，给自己领取了联盟礼遇券。业务已拍板：**活动工作人员不允许领取本活动联盟礼遇券**。

**已知样例（须纳入疑似自领清单）**

- 核销码 / 券码：`Y6P433DY7J8T`
- 现象：领取人手机号与发券人（issuer）手机号同为 `18702169501`（瑞虹太阳宫店，丽妍 V3–V5）
- 处理：列入疑似员工自领清单，供运营**人工作废**；**不要自动批量作废**除非另有指令

## 产品规则（必须实现）

1. 凡微信登录手机号能匹配到预录入工作人员名单（`Staff` / `tb_alliance_staff`，含丽妍与 GANO、**全部角色**：顾问、店员、店长、运营等）的账号，**禁止**联盟券领取（claim）成功。
2. 判定依据：登录态手机号 ∈ `Staff.mobile`（与现有员工鉴权一致）。
3. 拦截必须在服务端 **`POST /coupons/claim`（或等价 claim 写库接口）**、发券写库之前执行；前端可加 Toast/禁用，但**不得作为唯一防护**。
4. A/B 两个发券方向的领取入口（店铺页「立即领取」、领取详情页领取等）共用同一校验。
5. 失败时返回：
   - HTTP `403`
   - 业务码：`STAFF_CLAIM_FORBIDDEN`
   - 文案：**「活动工作人员不可领取本联盟礼遇」**
6. 不影响：工作人员亮码、扫码核销、看数等原有角色能力；不影响真实顾客领取。
7. 保留原有「本活动已领过」幂等与限量逻辑；**工作人员校验优先于发券成功**（建议顺序：登录 → 是否 Staff → 是否已领 → 库存 → 发券）。

## 历史数据（一并交付）

1. 提供查询：领取人手机号 ∈ 工作人员表 的已领有效券清单（字段至少：券码、券类型、领取时间、领取手机、发券手机、发券门店、状态）。
2. 清单中**必须包含** `Y6P433DY7J8T`（若仍有效/未作废）。
3. 默认只输出清单与作废操作说明；**不自动批量作废**。

## 实现要求

- 先定位：claim 接口、登录态取手机号、工作人员名单查询。
- 增加 `isAllianceStaff(mobile)`（或等价）校验；命中则拒绝写库。
- 补充用例：顾客可领；名单内手机号不可领；未登录先 401；已领仍走原重复领取逻辑。
- 输出：改动文件列表、关键 diff 说明、错误码、回归清单、疑似自领 SQL/脚本。

## 不要做

- 不要只改 UI 隐藏按钮。
- 不要用「核销前非会员确认」替代本拦截。
- 不要改动亮码 TTL、档位限量、核销主流程等无关逻辑。
- 不要自动批量作废历史券。
